# Ayurveda Data Pipeline — wise-eating extension

Source of truth for all Ayurvedic content added to the Ayura database.
The app's existing structure is preserved; this data extends it.

## Approved decisions (2026-07-21)

1. **Base project:** wise-eating original (this repo).
2. **USDA coverage:** all 12,601 foods get Ayurvedic properties, tiered:
   - `classical` — ~750 hand-authored dravyas (files in `dravyas/`)
   - `derived` — generic USDA foods inherit from their crosswalked dravya
   - `estimated` — processed/branded foods get category-level values via `rules/`
   The UI must always show the tier.
3. **Viruddha / contraindications:** warn, don't block. Informational badges +
   explanations; recipes flag viruddha pairings; nothing hidden.
4. **Recipes:** 1,500 AI-authored, classical-first (~300 classical, ~1,200
   dosha-tagged everyday), ingredients linked to dravyas/USDA IDs.

## Folder layout

- `canon/` — naming index (~631 dravya stubs + 133 recipe stubs, rescued from
  the previous project). Input worklist for authoring; not shipped.
- `dravyas/` — full-facet dravya batches, 25/batch, `batch-NN.json`.
  Target: 30 batches = 750 items.
- `recipes/` — recipe batches, 50/batch, `batch-NN.json`. Target: 30 batches = 1,500.
- `crosswalk/` — USDA fdcId → dravya mapping (`crosswalk.csv`), generated by
  name-matching then human-reviewed.
- `rules/` — category-level estimation rules for unmatched USDA foods.

## Dravya format (16-field facet)

Every item in `dravyas/batch-NN.json`:

| Field | Meaning / scale |
|---|---|
| `id`, `name`, `sanskrit`, `aliases`, `category` | identity |
| `edible` | whether the item is eaten as a portion; defaults to `true` when omitted |
| `inedibleReason` | required non-empty reason when `edible` is `false`; absent otherwise |
| `rasa` | tastes: sweet, sour, salty, pungent, bitter, astringent |
| `virya` | heating / cooling / neutral |
| `vipaka` | post-digestive: sweet / sour / pungent |
| `gunas` | qualities: heavy, light, oily, dry, sharp, soft, smooth, rough, penetrating, dense, liquid, slimy |
| `prabhava` | special effect, free text (empty if none claimed) |
| `dosha` | vata/pitta/kapha: −2 pacifies strongly … +2 aggravates strongly |
| `agniEffect` | effect on digestive fire, −2…+2 |
| `digestibility` | 1 very hard … 5 very easy |
| `seasons` | best ritus: vasanta (spring), grishma (summer), varsha (monsoon), sharad (autumn), hemanta (early winter), shishira (late winter) |
| `timeOfDay` | morning / midday / evening / night |
| `combinations` | good pairings (free text list) |
| `viruddha` | incompatible pairings (list; drives warn badges) |
| `contraindications` | who should be cautious (list) |
| `preparation` | how to prepare/use for best effect |
| `usda` | bindings: `{fdcId, name, tier}` — fdcId is the `ZID` in the preseeded store, verified |
| `servings` | `{label, grams}` |
| `provenance` | classical sources |
| `confidence` | `{ayur, sci}` 0–1 |

All items start `"qualityState": "aiDraft"`; an expert review pass promotes to
`reviewed` before release. Entries where classical sources disagree carry a
`reviewNote`.

## Recipe format

`recipes/batch-NN.json`, per item: `id`, `name`, `category` (classical |
everyday | international), `meal` (breakfast/lunch/dinner/snack/drink),
`servings`, `prepMinutes`, `cookMinutes`, `ingredients` (list of
`{dravyaId or fdcId, name, grams, note}`), `steps` (list), `dosha` (computed
from ingredients, then hand-adjusted), `seasons`, `timeOfDay`,
`viruddhaFlags`, `guidance`, `provenance`, `confidence`.

## Seeding strategy (keeps current app structure)

1. New SwiftData models, additive only (lightweight migration safe):
   `AyurvedaProfile` (1:1 with `FoodItem` via food id), plus recipes seeded as
   `FoodItem(isRecipe: true)` + `IngredientLink` rows — the machinery already exists.
2. Build script packs `dravyas/ + recipes/ + crosswalk/ + rules/` into
   `ayurveda_seed.json.gz` bundled with the app.
3. One-time seeder on first launch of the new version inserts profiles and
   recipes; derived/estimated tiers are computed on-device from crosswalk +
   rules (nothing stored for 12.6k rows in the bundle).

## Validation (every batch must pass)

- JSON parses; all enum values in-range; dosha/agni in −2…+2; digestibility 1–5.
- Every `usda.fdcId` exists in the preseeded store (`ZFOODITEM.ZID`).
- Every recipe ingredient resolves to a dravya id or fdcId.
- No duplicate ids across batches.
